## 意图

接续 [P0012](p0012-expert-grouped-dot-oracle.md) 与 [P0013](p0013-expert-grouped-dot-scalar.md)，为官方 `act_quant(x, 32, "ue8m0", float8_e8m0fnu)` 建立单行 CPU 规范参照：由 BF16 激活生成 E4M3FN 编码与 E8M0 scale，输出可直接作为 [COMPUTE](../docs/COMPUTE.md) 的 `a_codes`/`scale_a`。成功标准：按 [D0010](decisions/d0010-act-quant-reference.md) 契约独立验证的 Python 实现，与既有计算参照组合即得到从 BF16 激活出发的官方专家路径单输出参照。

本参照位于 sm120 原生路径 K-X1 与 FP8 线性层激活侧的上游，也是 K-E1 质量偏差"从共同量化前激活"测量的前置（[MODEL §4](../docs/MODEL.md#4-精确性链条)）。不验收 K-X1 kernel、官方 GPU、K-E1 质量偏差或端到端一致，不改变 W4A16 decode 默认规划。

## 验收

- [x] **开工前置决策**：2026-10-13 用户审议通过 D0010 与本项当前范围，D0010 accepted，本项转为 active；输入域、BF16 位级解码边界、scale 指数规则、商的 binary32 舍入与下溢、元素编码与零符号、非有限输入、观测方式、归档位置与待设备仲裁项已明确。实现与技术验收尚未开展。
- [x] **一个入口、一行输入**：`ref/` 新增独立模块（暂名 `ref/act_quant.py`），以一维 BF16 原始位为输入，`K > 0` 且整除 32，输出 K 个 E4M3FN 编码与 K/32 个 E8M0 编码；第 j 组 32 元素只决定 `scale[j]`。不支持 128 元素组、FP32 非幂 scale、inplace、FP32 输入或矩阵/批量，不隐式补齐或广播。非法输入按 D0010 抛 `ValueError`/`TypeError`，不返回部分结果。不改写 `ref/formats.py`、`ref/dequant.py`、`ref/compute.py`。
- [x] **量化与舍入独立验证**：期望由独立精确算术与逐步舍入构造，不调用被测 BF16 解码、amax、scale、除法或编码 helper。scale 指数对全部有限 BF16 amax 与精确 `ceil(log2(max(amax, fl32(1e-4))/448))` 逐一比较，并证明 `amax/2^e ≤ 448`（`clamp` 不可达）；元素编码覆盖全部有限 BF16 码点在边界指数下的结果，非有限码点全部拒绝。商按精确 `x / 2^e` 经一次 binary32 RNE、渐进下溢且保留零符号，不采用 DAZ/FTZ；再经 clamp 与 E4M3FN RNE 编码。每组 amax 位、下限后值位、乘积位、指数与 scale 编码，以及每元素商位、clamp 后的编码前位与编码分阶段按位检查，不以最终编码相同替代阶段位一致。
- [x] **边界与布局**：以下定向用例均必选，随机用例仅作固定种子补充。
  - E4M3FN RNE 中点及两侧、次正规边界（`2^-10` 舍入为零、`2^-9` 最小次正规）、448 上界、正负零与 `−0 → 0x80`；amax 恰为 `448×2^k`（指数取 k 而非 k+1）、低于下限与全零组（指数 −22）。
  - 低于下限的非零组：全组 `2^-14` 的商为 256，编码 `0x78`，不得因 amax 下限清零。
  - BF16 次正规输入：`0x0001/0x8001` 与其余元素全零的组，amax 位为 `0x00010000`，商为 `±2^-111`，最终编码为同号零。
  - 商的 binary32 次正规与下溢边界：同组 `amax=448×2^23` 或 `448×2^24`、小元素 `±2^-126`，前者商为 `±2^-149`（最小 binary32 次正规），后者为 `±2^-150`（RNE 中点舍入为同号零），并覆盖中点两侧；不以最终 E4M3FN 均为零掩盖阶段位差异。
  - 相邻组 scale 不同的多组，以及跨 128 元素边界、能识别"每四组共享 scale"的错组用例。
- [x] **与计算参照组合**：输出直接喂给 `ref/compute.py::expert_grouped_dot`，在定向向量上与独立构造的单输出期望一致；只作为测试，不新增组合入口，不以组合结果代替分阶段验证。
- [x] **测试敏感性与失败传播**：在独立临时副本中分别注入：指数改用 floor 或 round；每四组共享 scale；E4M3FN 截断或中点远离零；`−0` 规范化为 `+0`；去掉 amax 下限；BF16 次正规解码冲为同号零；binary32 商次正规冲零；binary32 商中点远离零。每类由指定定向用例产生数值或阶段位比较失败，恢复后全部通过、源字节不变；仅异常或进程故障不作为语义敏感性证据。BF16 解码与商阶段的注错即使不改变最终 FP8 编码，也必须由阶段位比较检出。用精确 `1/448` 代替 `fl32(1/448)` 在 BF16 输入上不改变指数、scale 与最终编码，但不保证乘积阶段位相同；不新增其为必选敏感性变体。错误结果或异常使入口非零退出，必选用例无 skip。
- [ ] **CPU 独立复现**：一条 Python 命令运行全部必选验收，仅依赖标准库，不初始化 Torch/TileLang/CUDA，不依赖目标机、权重或设备 dump；接入全量 CPU Debug/Release 的 CTest，不扩大 `cpu-asan`。从源码目录外及干净检出复现，既有格式、计算与仓库检查回归通过，`check_repo.py --strict` 与提交范围审计 E=0 W=0 I=0。

### 开工前评审证据

- 环境：Python 3.12.8（conda-forge），Linux 5.15.0-72-generic x86_64，Intel Xeon Platinum 8350C。方法：临时标准库探针（未入库），binary64 精确积经 `struct` 转 binary32（默认 RNE 环境）模拟官方 FP32 阶段，`Fraction` 求精确 `ceil(log2)`。仅为设计证据，不替代本项独立测试。
- `fl32(1/448)` = `0x3B124925`，相对 1/448 偏大约 `4.47e-8`。
- 全部正有限 BF16 amax（`0x0000`～`0x7F7F`，低于下限取 `fl32(1e-4)`）：官方阶段指数与精确 ceil 无一不同；指数范围 −22～120，E8M0 `0x69`～`0xF7`；故 `amax/2^e ≤ 448`，`clamp` 对 BF16 输入不可达。
- 下限 `1e-4` 落在 `(448·2^-23, 448·2^-22]` 内，其具体浮点表示不改变指数。[算]

### 复评边界证据

- 环境同上。方法：临时标准库 `Fraction` 探针从 BF16/E4M3FN 位域独立构造精确有理数，不调用既有解码或舍入 helper。BF16 `0x3880` 为 `2^-14 < 1e-4`，除以 `2^-22` 得 256，对应 E4M3FN `0x78`；BF16 `0x4F60/0x4FE0` 分别为 `448×2^23` 与 `448×2^24`，同组 `0x0080`（`2^-126`）的精确商分别为 `2^-149` 与 `2^-150`；BF16 `0x0001/0x8001` 除以 `2^-22` 得 `±2^-111`。[算] 仅确认定向用例，不替代本项舍入与阶段位独立验收。
- 环境同上。方法：子进程通过临时辅助库设置默认 MXCSR `0x1F80` 或 DAZ `0x1FC0`，调用仓库实际 `decode_bf16` 后再取 `fp32_bits`；恢复保存的 MXCSR 并删除临时文件。默认环境下 `0x0001/0x8001` 得 `0x00010000/0x80010000`，DAZ 下得 `0x00000000/0x80000000`。这证明本机既有值级解码边界不满足本项阶段位环境无关性要求；不改写既有 oracle 或外推其他平台，新模块按 D0010 使用原始位构造。
