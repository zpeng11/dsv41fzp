## 背景与问题

[P0027](../p0027-fp8-grouped-dot-oracle.md) 为共享专家补齐 FP8×FP8 计算参照。官方 FP8 GEMM 的数据格式与权重 scale 布局不同于既有 FP8×FP4 路径；源码给出了计算阶段，但不能确定设备内部归约、融合与转换的逐位语义。D0008 及旧点积的验收不自动覆盖新路径。

## 决策驱动

- 先确定可由独立精确算术复核的 CPU 契约，再实现参照及后续同契约生产 scalar。
- 保留官方计算阶段与模型实际分组，明确项目选择和待设备仲裁项，不用逐元素反量化替代计算契约。
- 复用已验收格式、激活量化与必要算术构件，不修改旧 oracle，也不建立通用软件浮点层。
- 按 D0011，数值正文集中在 COMPUTE，覆盖矩阵归 MODEL，实际操作归 BUILD；本 D 只留选择理由。

## 备选方案

- **官方阶段约束下的独立 CPU 规范**：采纳。确定性的顺序归约、显式舍入及 scale 落点便于逐阶段独立核验；环境保证不依赖调用方浮点模式。不以这些选择推断官方 GPU 等价。
- **直接继承 FP8×FP4 验收**：不采纳。权重码点域和二维 scale 布局不同，共用算术政策不能替代新路径的独立期望与错误检出。
- **逐元素 dequant 后点积，或合并 scale、重排/融合、提前转换**：不作为本参照。它们改变舍入落点，须另外验证等价性或质量，不能默认为同一计算契约。
- **等待设备 dump 才建立 CPU 参照**：不采纳。把可独立完成的 CPU 规格与设备等价性捆绑；设备仲裁仍是后续独立义务。
- **新建一页复制既有算术政策**：不采纳。采用 [COMPUTE §8](../../docs/COMPUTE.md#8-fp8-块缩放单输出点积) 独立规定新输入域与执行链，按明确引用共享既有舍入和特殊值政策，避免两份可修改正文。

## 结论

2026-10-16 用户审议接受本设计并授权推进实现，本决策转 accepted。

采用 COMPUTE §8 的契约：为 FP8×FP8 建立独立单输出参照与同核心观测，以独立期望验证新的完整执行链；二维权重 scale 仅在测试侧选行组合，不扩展矩阵 API。官方阶段、项目 CPU 选择和设备待仲裁项均以该节为唯一数值来源。

## 后果

- P0027 开工前置决策成立，可依用户授权启动参照编码；实现验收与人工结项仍按 P0027 执行，提交和合并另依仓库程序。
- 新增测试须逐阶段验证两种输出、二维 scale 选行及既有激活量化实际输出的消费，并以完成调用后的数值差异证明错误检出；不重跑旧组件全量套件。
- 实现到位后再更新 MODEL 覆盖矩阵与 BUILD 复现入口，不提前登记未存在的能力或命令；最终知识与证据仍由 P0027 人工审议。
