## 背景与问题

[P0012](../p0012-expert-grouped-dot-oracle.md) 建立已编码 FP8 激活 × packed FP4 权重的单输出计算参照。既有格式与逐元素反量化参照不规定归约及 scale 应用的舍入边界；官方源码也不能确定 `T.gemm` 内部归约、编译后融合和设备 cast/FTZ。P0012 的 CPU 评审反例证明这些选择会改变合法输入的结果，但不证明哪一种更接近官方 GPU。

## 决策驱动

- 参照先于同契约生产实现建立，结果须能由独立精确算术与逐步舍入复核，不依赖官方 GPU 栈。
- 保留官方模型的固定分组和运算阶段，明确区分源码事实、项目 CPU 语义与待设备仲裁的细节。
- 官方 FP8×FP4、K-E1 W4A16 与 K-E2 整数改写的实现 parity 和跨路径质量偏差分别验收。

## 备选方案

- **官方阶段约束下的 CPU 规范参照**：选择顺序 FP32 累加、各步独立 RNE、无融合和渐进下溢。次序确定、便于逐阶段独立验证，可为后续 scalar 提供明确契约；不是对官方 GPU 归约的推断：采纳。
- **直接镜像官方 GPU 逐位语义**：源码不足以确定归约、融合和 cast/FTZ，缺少设备仲裁证据：否决。
- **精确求和后一次舍入、先逐元素 dequant，或折叠 scale、重排、融合、提前 BF16、整数改写**：改变数值契约，不作为本参照；不因此断言这些方案错误，其等价性或质量须另验。
- **等官方 GPU dump 后再建立 CPU 参照**：将确定 CPU 契约与设备等价性捆绑，阻塞无需设备的交付：否决。宣称 GPU 等价仍须设备验证。

## 结论

2026-10-12 经用户确认接受；不扩为编码、提交、合并或人工结项授权。

1. 在 `ref/` 建立独立计算分支，按 [MODEL §4](../../docs/MODEL.md#4-精确性链条) 路由，不挂为逐元素 dequant 的已验证后继。
2. 数值契约唯一归档于 [COMPUTE](../../docs/COMPUTE.md)：按 K 顺序逐步 FP32 RNE，先激活 scale 后权重 scale，不融合、不折叠、不重排，渐进下溢，仅最终转换 BF16；输入、输出和特殊值规则以该页为准。
3. 计算与宿主浮点环境无关，不改写既有格式 oracle；分阶段观测同一执行路径，期望由独立精确算术和舍入构造。

## 后果

- 不取代 D0007，不改变 W4A16 decode 默认规划。验收后的 Python 参照只供后续同契约 scalar 对照，不直接验收 K-E1/K-E2、官方 GPU 或端到端一致。
- COMPUTE 保留契约，MODEL/QUANT 提供路由；实现、测试及评审证据集中于 P0012，实际复现入口与环境到位后归档 BUILD。
- P0012 前置决策成立，其余验收及人工结项要求不变；未来生产实现、跨路径质量和设备验证须独立验收。
