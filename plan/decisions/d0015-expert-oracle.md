## 背景与问题

[P0020](../p0020-expert-oracle.md) 接续已结项 P0019；官方 `model.py:841–851` 确定专家结构，但 `F.silu` 未规定 CPU exp 近似及内部舍入。既有量化与点积参照不能单独确定非线性及跨阶段失败语义。

## 决策驱动

- 为后续生产专家提供独立验证的上一级，不因实现方便改动既有参照。
- 保持官方运算顺序及 BF16 落点，区分 CPU 规范与 GPU 逐位等价。
- 限于标准库、单 token FP4 专家，不扩成通用数学库或平台浮点适配层。

## 备选方案

- 宿主 `math.exp` 或 Torch 直接作真值：不采纳，缺少独立正确舍入证据。
- 自行规定 exp/add/div 各自 FP32 舍入：不采纳，官方调用没有规定这些内部阶段，会额外引入算法契约。
- 实数 SiLU 一次正确舍入 FP32，Decimal 区间认证、独立 Fraction 级数验证：采纳，定义紧凑且能对舍入作出认证。
- 为 Decimal 保存恢复硬件状态或替换私有标准库实现：不采纳，超出慢参照需求。验证已发现内部会新增 inexact 标志，故明确异常屏蔽及 sticky 状态边界，而非声称完全无副作用。

## 结论

2026-10-15 用户审议代码通过，授权依 D0011 精简归档、提交并合并；接受随候选实现提交的数值与环境边界。本决策转 accepted，完整可维护契约归 [EXPERT](../../docs/EXPERT.md)，不在此重复接口与逐步规则。

选择正确舍入 SiLU、显式 BF16 边界和 w2 前外部权重乘法；桥接允许观察非有限值，完整专家在实际激活量化边界拒绝非有限输入。复用既有量化与点积，普通入口与 trace 共用核心。允许 Decimal 新增 sticky 标志、不修改控制位或清除已有状态，不放宽既有 scalar 契约。

## 后果

- 三矩阵需检查全部阶段；最终 BF16 相同不足以排除被量化掩盖的错误。
- 未来 libm/SIMD/GPU 实现须独立满足该契约，或另立不同契约；不由 CPU 参照推定官方 GPU 等价。
- 契约正文只在 EXPERT，覆盖边界只在 MODEL §4，命令只在 BUILD §7，验收证据只在 P0020。
