## 背景与问题

P0009 起 P 条目平均体量约为 P0001–P0008 的 3.4 倍（约 8.2k 对 2.4k 字符），D 约 2 倍；同期生产代码仅 `src/quant` 约 900 行。增量主要不是新知识，而是：P 记录按评审轮次只追加不合并；同一数值契约在 P 验收、D 备选与 docs 中各写一遍；"不验收 K-X1/K-E1/K-E2/官方 GPU/端到端"类边界清单在 QUANT、COMPUTE、ACTQUANT 与 STATUS 中重复；同一实测环境串散落 11 个文件；ACTQUANT §5 混入敏感性门禁等验收过程细节。现行规则未约束这些写法，须决定写作约定及存量处理。

## 决策驱动

- D0003 的职责划分不变：长期知识进 docs，理由留 D，原始证据留 bench，P 只留过程、验收证据与归档指针。
- 每个事实只有一处可修改的正文，其余位置链接；删除重复不得丢失事实或测量环境。
- 提交与 P/D 编号引用须保持可解析；`check_repo` 不校验 docs 锚点，锚点断裂不会被机械发现。
- 不修订 AGENTS.md，不改变 P/D 状态机与收尾字段。

## 备选方案

- 维持现状，仅靠评审提醒：已证明不收敛，否决。
- 给 P/docs 设硬性字数上限并入 `check_repo`：数值契约天然密集，硬限易诱发拆页或省略事实，否决；模板给软上限即可。
- 约定单一来源并改模板，存量只对未来生效：保留历史原貌，但约 9.7 万字符存量不减，备选。
- 约定单一来源并改模板，同时压缩已结项 P 记录：采纳。git 历史保留原文，记录内留压缩前提交指针，证据可追溯。
- 同时改写已 accepted 的 D：D 是决策时点的理由，改写会混淆当时依据与事后整理，否决。

## 结论

2026-10-13 经用户审议通过，P0015 同步转为 active。结论：

1. **单一来源**：验证链"覆盖什么、不覆盖什么"只写在 MODEL §4 的覆盖矩阵；实测环境在 BUILD §1 具名定义，其他位置引用名称；数值契约正文只在 docs，D 写选择与理由，P 验收引用 D/docs 章节而不重述规则；验收方法细节与敏感性门禁属于 P 证据，docs 只留复现入口与方法要点。
2. **P 模板**：「记录」固定为范围与依据、最终证据、评审处置、提交四块。证据只记最终有效的一次；中间轮次仅在推翻或改变结论时各留一行；授权登记每次一行（日期与授权范围），不写否定式免责。
3. **已结项 P 压缩**：仅改 `## 记录` 与验收条目的措辞，front matter 字段与状态不变（`updated` 可改），`## 收尾` 三项语义不变；记录末尾注明压缩前全文所在提交。已 accepted 的 D 不改。
4. **docs 锚点**：标题文字不变；确需改动时同提交修正全部引用。
5. **STATUS**：「当前阶段」只写能力边界；每个入口一行，含入口名、契约链接与证据 P，边界一律指向 MODEL §4。

- 后续 P/D 按本约定写作；评审以"是否另有唯一来源"判定重复。
- 不修订 AGENTS.md，不扩展 `check_repo`；锚点核对在 P0015 中以脚本一次性完成，不入库为门禁。
