## 背景与问题

[P0014](../p0014-act-quant-oracle.md) 要为官方 `act_quant` 建立 CPU 参照：BF16 激活每 32 元素求 amax，生成 2 的幂 scale，把元素编码为 E4M3FN，scale 存为 E8M0。专家 FP4 与 FP8 线性层都按 `act_quant(x, 32, "ue8m0", float8_e8m0fnu)` 调用（`model.py:27–30,181–198`），专家三个线性层的输入都是 BF16（`model.py:841–851`）。[COMPUTE](../../docs/COMPUTE.md) 只接受给定的编码与 scale；[QUANT §5](../../docs/QUANT.md#5-验证链边界) 明确既有 oracle 不证明有损量化与 scale 生成。

官方源码给出阶段（`kernel.py:22–38,74–91`）：`T.reduce_absmax`、`T.max(amax, 1e-4)`、FP32 乘 `1/448` 后以位域取 ceil(log2) 得 2 的幂、`clamp(x/s, ±448)` 后写入 FP8、scale 写入 E8M0。源码不能确定 `reduce_absmax` 与 `T.max` 遇 NaN 的语义、编译后是否启用 fast-math/FTZ、除法的具体指令以及 FP8/E8M0 cast 的舍入与饱和实现。须决定 CPU 参照的输入域、scale 规则的表述、元素编码与特殊值、观测方式与契约归档位置。

## 决策驱动

- 技术约束：参照须能由独立精确算术与逐步舍入复核，不依赖官方 GPU 栈与宿主浮点环境；输出须能直接作为 COMPUTE 的 `a_codes`/`scale_a`。
- 技术约束：开工前评审探针（证据见 P0014）显示，对全部有限 BF16 amax，官方 FP32 阶段与精确 `ceil(log2(max(amax, fl32(1e-4))/448))` 得到相同指数，范围 −22～120（E8M0 `0x69`～`0xF7`），因此 `clamp ±448` 对 BF16 输入不可达；下限 `1e-4` 落在 `(448·2^-23, 448·2^-22]` 内，其具体浮点表示不改变指数。这些须由 P0014 独立测试固化后才能作为契约事实。
- 技术约束：BF16 至多 8 位有效数，除以 2 的幂在 binary32 正规范围内精确；落入 binary32 次正规范围（< 2^-126）的商远小于 E4M3FN 最小次正规的一半（2^-10），无论精确、舍入或保号冲零，最终 E4M3FN 编码都是同号零。但最终编码相同不代表编码前 binary32 位相同，商的舍入、下溢与零符号仍须明确，并由阶段位比较独立验收。
- 项目约束：沿用 D0008——保留官方固定分组与运算阶段，区分源码事实、项目 CPU 语义与待设备仲裁项；不改写既有格式与计算 oracle，不建通用软件浮点 API 或第二个格式配置中心。
- 项目约束：K-E1 质量偏差须"从共同量化前激活"测量（[MODEL §4](../../docs/MODEL.md#4-精确性链条)），本参照是其前置，但不承担质量验收。

## 备选方案

### 参照范围与输入域

- 只覆盖模型实际使用的变体：一维 BF16 原始位输入，`K > 0` 且整除 32，固定每 32 元素一组、2 的幂 scale、E8M0 存储、非 inplace；输出 K 个 E4M3FN 编码与 K/32 个 E8M0 编码：采纳。与 COMPUTE 的分组和单行边界一致。
- 同时覆盖 inplace 量化后反量化（SWA/KV，`kernel.py:81–86`）、`fp4_act_quant`（indexer 与主 KV）、128 元素组或 FP32 非幂 scale：前两者属 KV 路径（K-A2/K-A5），后两者模型未使用：不采纳，另项决定。
- 接受 FP32 输入：官方专家与 FP8 线性层输入均为 BF16，不扩大模型实际输入域，也不将本次 BF16 域上的 scale 指数等价性证明外推到 FP32：不采纳。

### scale 指数规则

- 契约按官方阶段表述：精确 amax → 与 `fl32(1e-4)` 取大 → 与 `fl32(1/448)` 做一次 binary32 RNE 乘法 → 位域 ceil(log2) → `2^e`；独立期望用精确有理数 `ceil(log2(max(amax, fl32(1e-4))/448))`，二者在全部有限 BF16 amax 上逐一一致作为验收证据：采纳，推荐。与源码阶段逐行对应，期望不依赖被测算术。
- 契约只写精确有理数定义：更简洁，但与源码阶段的对应须另行论证，未来扩展输入域时等价性不自动成立：不采纳。
- 契约只镜像 FP32 阶段、期望也用 FP32 复算：期望与被测同构，不能独立发现错误：否决。

### 元素编码与特殊值

- 商为精确 `x / 2^e` 经一次 binary32 RNE（中点取偶），采用渐进下溢，不采用 DAZ/FTZ；原始零与下溢到零均保留输入符号。该结果立即落为 binary32 位，随后保留 `clamp ±448` 阶段，再按 E4M3FN RNE（中点取偶、渐进下溢）编码；零保留符号，`−0` 编码为 `0x80`：采纳。这是项目 CPU 语义，不推定官方 GPU 的除法指令或下溢行为。
- 全零组或 amax 低于下限：指数取 −22（scale `0x69`）；全零组的元素编码为同号零，低于下限的非零元素仍按商与 E4M3FN 编码规则逐元素量化，不因 amax 下限而清零：采纳，跟随源码下限。
- 拒绝 BF16 NaN/Inf 输入：源码对非有限输入的行为取决于 `fmaxf` 与 cast 语义，无法确定，CPU 参照不定义：采纳。不宣称官方入口也拒绝。
- 错误类沿用 COMPUTE §2：空输入、长度或分组错误、超宽或负编码、非有限输入抛 `ValueError`，非整数编码抛 `TypeError`；先校验元数据，再校验全部内容，最后计算，不返回部分结果：采纳。

### 观测与环境

- 普通入口与阶段观测共享同一执行路径：每组记录 amax 位、下限后值位、乘积位、指数与 scale 编码，每元素记录商的 binary32 位、clamp 后的编码前 binary32 位与 E4M3FN 编码；不另写测试专用量化：采纳，沿用 COMPUTE §4。阶段位是契约的一部分，最终编码相同不能替代阶段位一致。
- BF16 解码仅复用 QUANT §2 与既有格式 oracle 的 `bf16_bits << 16` 位映射及其验证依据，在新模块内从原始位直接构造 binary32 位；不调用返回宿主浮点值的 `decode_bf16`/`fp32_from_bits`，不改写既有格式 oracle：采纳。既有值级 API 的宿主浮点转换边界不足以支持本项的环境无关性保证。
- 仅依赖 Python 标准库；BF16 解码、amax、scale 计算、商、clamp、编码及阶段观测全程以整数位域构造，不经宿主 float 往返，不读取或修改调用方浮点环境，与宿主舍入模式及 DAZ/FTZ 无关；不初始化 Torch/TileLang/CUDA：采纳。

### 契约归档位置

- 新建 `docs/ACTQUANT.md`，QUANT §5、COMPUTE 与 MODEL §4 只加路由：采纳，推荐。与 COMPUTE 同为独立契约，后续生产 C++ 节有固定去处，不扩大既有两页的声明范围。
- 并入 QUANT 新增一节：QUANT 声明为格式与给定 scale 反量化，且已含两节生产 C++，继续膨胀并改变其声明范围：备选。
- 并入 COMPUTE：`act_quant` 同时服务 FP8 线性层，超出"专家分组点积"的页面范围：不采纳。

### 待设备仲裁项

`reduce_absmax`/`T.max` 的 NaN 语义、fast-math/FTZ 是否生效、乘法与除法指令、FP8 与 E8M0 cast 的舍入与饱和实现、多行分块对单行结果无影响，均不由本参照决定。本参照不宣称官方 GPU 逐位等价。

## 结论

2026-10-13 经用户审议通过，接受本决策及 P0014 当前范围；本决策转为 accepted，P0014 同步转为 active。本次仅登记审议结果并提交计划，不开展实现与技术验收。结论：

1. 在 `ref/` 新建独立模块，作为官方动态激活量化的 CPU 规范参照，输出可直接作为 COMPUTE 的 `a_codes`/`scale_a`；E4M3FN 有损编码只在该模块内构造，不改写既有格式与计算 oracle。
2. 输入域、scale 指数规则、元素编码、特殊值与错误类按上节采纳项；契约正文在接受后归档 `docs/ACTQUANT.md`。
3. 阶段观测共享执行路径；amax、下限后值、乘积、商及 clamp 后值均以原始 binary32 位记录并独立验证，不以最终编码相同替代阶段位一致；期望由独立精确算术与逐步舍入构造。

## 后果

- 不取代 D0008/D0009。本参照是后续同契约生产 C++ scalar 的上一级，不直接验收 K-X1 kernel、官方 GPU、K-E1 质量偏差或端到端一致。
- QUANT §5 中"不证明有损量化、scale 生成"的边界在归档时改为路由到新页面，不改写既有格式契约。
- 生产 C++ 的接口、数值路径与模块归属（`src/quant` 或 `src/aq`）另立决策。
