## 背景与问题

[P0024](../p0024-router-scalar.md) 将 P0023 参照落为生产 C++。数值阶段与选择规则已有 [D0018](d0018-router-reference.md) 和 [ROUTER](../../docs/ROUTER.md)，但 FP32 softplus 不能复用 BF16 SiLU 全域表；生产接口、认证资源和失败保证尚须确定。

## 决策驱动

- 复用既有整数 FP32 原语，生产运行不依赖 Python、libm 或外部高精度库，不改 oracle。
- router 归 core，只补该算子需要的私有整数能力，不展开公共数学或调度框架。
- 固定大小结果只在完整成功后交付；调用方持有阶段工作区，不为失败回滚重复整个计算。
- 按 D0011 分工记录理由、契约与证据，不重复数值公式。

## 备选方案

- 宿主 libm 或复合函数一次舍入：不采纳，不能满足既有阶段正确舍入与环境保证。
- FP32 全域表或引入外部任意精度库：不采纳，前者体量不合适，后者增加本项不需要的部署依赖。
- 为固定大小结果引入输出 span 及回滚：不采纳，采用按值返回，工作区仍显式借用。
- 私有定宽整数外向区间认证：采纳，有限资源、可检查包围关系，认证失败显式拒绝。

## 结论

2026-10-15 用户批准 P0024 开工方案，接受本决策的接口、算法及失败取舍，授权实现、必要知识归档和增量验证；本轮不提交 Git，最终人工验收另行进行。

- router 独立归 core，私有复用 quant 原语；不以复用为由扩大 quant 职责或迁移整个数值核心。
- 采用按值结果和借用阶段工作区，避免固定大小输出的回滚及观测副本；参数与运行中失败分层处理，不为 scratch 回滚重复计算。
- 采用私有定宽整数区间而非表枚举或外部数学依赖，以有限资源认证正确舍入；不能认证就显式失败，不能将实现预算变成数值容差。
- core sanitizer 独立分域，避免重跑 quant-only 验收；专家组合继续复用既有连接，不扩协议与调度。

具体接口、资源与失败/环境保证唯一归 [ROUTER §6](../../docs/ROUTER.md#6-生产-cpu-scalar)，构建与验证入口归 [BUILD](../../docs/BUILD.md)。

## 后果

- 定宽运算的容量上界、区间余项与最终舍入须有独立证据；不以增加精度代替正确包围。
- 合法输入可能因认证资源耗尽而失败；私有探针可耗尽预算，公共 API 不暴露精度旋钮。
- 生产接口及算法保证归 ROUTER，操作与环境归 BUILD，覆盖路由归 MODEL，最终证据归 P0024；不改变 D0018 或既有 quant 契约。
