## 背景与问题

[P0023](../p0023-router-oracle.md) 补齐已验收专家上游的编号选择与权重生成。官方 `model.py:809–827` 给出 FP32 gate、softplus/sqrt、选择和归一化阶段，但没有确定 GEMM 累加、非线性舍入及 top-k 平局行为；既有专家点积和 SiLU 契约不能直接覆盖这些运算。

## 决策驱动

- 为后续生产 router 建立独立验证的上一级，保留官方阶段而不推定 GPU 逐位等价。
- 限定主干配置和单 token，使用标准库，输入输出保持原始位编码并能直接衔接已有专家。
- CPU 数值不依赖宿主浮点控制，测试期望不能与被测非线性或舍入核心同源。
- 不为本项改写既有 oracle 或引入通用数学、tensor 与调度框架。

## 备选方案

- 仅实现给定分数后的 top-k：不采纳，未能从 token 激活生成实际路由。
- Torch/libm 输出作为真值：不采纳，不能独立认证内部舍入或跨环境稳定性。
- 理想复合 `sqrt(softplus(x))` 一次舍入：不采纳，跨越官方两个张量操作的 FP32 落点。
- 分阶段正确舍入、显式有序归约与编号平局规则：采纳，可认证、可复现，且明确区别于 GPU 算法。
- 绑定发布尺寸、不允许缩小合成矩阵，或扩为任意路由配置：均不采纳；固定主干算法参数，允许缩小 N/K 以独立验证边界。

## 结论

2026-10-15 用户批准 P0023 开工方案及本决策，授权短命分支实现、必要知识归档、增量验证与本地提交；最终人工验收另行进行。完整契约拟归 `docs/ROUTER.md`（随实现建立），模型参数依据只归 [MODEL](../../docs/MODEL.md)。

选择逐项 FP32 RNE 乘加、分阶段认证 softplus 与精确 sqrt、加 bias 后按分数降序且同分编号升序选择、从未加 bias 分数生成权重，以及按返回顺序归约。保持 softplus 默认阈值分支；非线性不能认证时失败，不猜测。有限输入不保证投影不溢出，投影乘积/累加或选择分数非有限时拒绝。普通与 trace 共用核心，入口完整校验快照；保留浮点控制及既有 sticky，允许 Decimal 新增 sticky，不承诺完整环境无副作用。

## 后果

- top-k 平局、累加次序和正确舍入是本项目 CPU 选择，不代表官方 GPU 规则；后续其他数值契约须另行验证。
- 保留源码阶段不等于每个差异都有数值反例；不强制要求“移除 softplus 阈值分支”能在 FP32 中检出。
- 既有参照数值 helper 可复用，新测试使用独立格点与级数区间；不修改已有专家数值语义或执行器协议。
- 数值契约只在 ROUTER，覆盖边界只在 MODEL §4，操作入口归 BUILD，P0023 留验收证据。生产 router、完整 MoE 与结项不在本次授权内。
