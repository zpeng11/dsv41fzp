## 背景与问题

[P0021](../p0021-swiglu-bridge-scalar.md) 接续 P0020 的已验收 `swiglu` 参照。生产侧须满足 [EXPERT §2](../../docs/EXPERT.md#2-运算与舍入) 的一次正确舍入 SiLU、逐次 FP32 RNE 乘法和显式 BF16 落点，但宿主 libm 不承诺正确舍入，也会引入平台与浮点环境依赖；运行时多精度区间算法则超出生产 scalar 的成本与维护目标。

## 决策驱动

- SiLU 输入仅来自 BF16 精确拓宽并完成 gate 钳位，定义域有限，可穷举而无需设计通用数学库。
- 表或算法必须逐项受 P0020 oracle 与独立边界期望约束；最终 BF16 相同不能掩盖中间阶段错误。
- 运行时须独立于调用方舍入、FTZ/DAZ 与 sticky flags，并复用既有整数位级 RNE 基础。
- 生成物不得进入 git；构建失败不得静默降级为近似 SiLU。
- 接口须明确区分完全省略 route-weight 乘法与显式乘权重，且能被后续完整专家直接消费。

## 备选方案

- 宿主 `std::exp`/`expf` 或 libm 加经验修正：不采纳；ENV-A 实测不能证明所有输入正确舍入，且浮点环境行为不满足确定性目标。
- 每元素运行整数或多精度区间算法：不采纳；可证明但实现面和运行成本过大，更适合作为 oracle 或生成期工具。
- 提交完整或压缩静态表：不采纳；完整表是生成物，压缩又引入索引/解压证明义务。
- 构建期生成完整 BF16 表、运行时纯整数查表：采纳；有限域可穷举，运行时只有钳位、索引及既有位级乘法/转换。

## 结论

2026-10-15 用户审议 P0021 开工方案并批准实施，本决策转 accepted。

- 标准库生成器枚举全部 65,536 个 BF16 code，调用 P0020 已验证的钳位与 SiLU oracle，在构建目录生成私有 `BF16 code → FP32 bits` 表；源码树不保存生成表。生成器缓存重复钳位结果，并以固定表字节 SHA-256 拒绝未经审议的数值变化。任一码点不收敛、摘要不符或写入失败均使构建失败。
- 运行时先执行 gate 非对称钳位，再按钳位后的 BF16 code 查表。未钳位的正有限 `>10` 与 `+Inf` 表项使用不可达哨兵，遗漏钳位不能偶然得到合法结果。表不压缩，避免增加新的数值变换。
- 公共 API 提供无权重与显式有限 FP32 权重两个重载。无权重重载完全省略第二次乘法；显式权重即使输入为空也先验证。gate/up 等长，可为空且 read/read 可重叠；实际输出前缀须与两输入分离。
- 非有限 gate/up 按 EXPERT 传播，不作为输入错误。元数据、权重、容量、字节计数与别名在读取输入元素和写输出前全部验证；拒绝时输出不变。
- SiLU 仅为生产桥私有实现，不成为通用 API。运行时钳位、查表、特殊值完备 FP32 乘法和 BF16 RNE 全用整数位运算，成功、trace 与拒绝路径均承诺完整 MXCSR 不变。

## 后果

- 构建依赖 Python 生成步骤和 P0020 oracle，但不新增外部包；生成头只存在于构建目录。表约占 256 KiB 私有只读数据，不据此作性能论断。
- 新增私有特殊值完备 FP32 乘法 wrapper，不改变既有 `multiply_finite` 的有限操作数契约。
- P0021 必须穷举全部 BF16 gate code，并另用不复用生产表的 Fraction/Taylor 边界期望验证；生成摘要不是数值验收的替代品。
- 本决策只覆盖 SwiGLU bridge。W1/W3 双投影、第二次激活量化、W2、完整专家失败原子性、SIMD/CUDA 与融合另行立项。
