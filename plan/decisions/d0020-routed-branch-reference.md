## 背景与问题

[P0025](../p0025-routed-branch-oracle.md) 组合既有路由和完整 FP4 专家，补齐多专家聚合。官方 `model.py:893–904` 在 FP32 中按专家编号累加，加入共享专家后才转换 dtype；路由返回次序与该循环不同，单专家最终输出还允许非有限值，须明确组合边界。

## 决策驱动

- 复用已验收组件，不为组合改写旧 oracle 或引入宿主浮点依赖。
- 不移动专家内部权重与量化落点，不在共享支路接入前引入额外 BF16 舍入。
- 普通与观测共用核心，参数错误在数值计算前暴露；范围限单 token routed 分支。
- 依 D0011，契约正文只在 MOE，理由留本决策，证据留 P0025。

## 备选方案

- 按 top-k 返回次序求和：不采纳，与官方单进程专家循环顺序不同。
- routed 输出先转 BF16，或在聚合处施加路由权重：不采纳，分别增加舍入或改变专家内部语义。
- 只验证选中专家，或按需回调加载专家：不采纳；本项采用完整只读专家表，使校验与快照边界明确，不引入加载器或调度协议。
- 拒绝最终专家非有限值：不采纳，既有专家允许这些结果；聚合沿用既有加法传播，不因新组合层收窄上游合法结果。
- 扩为共享 FP8 专家与完整 MoE：不采纳，需要独立 FP8 计算契约，超出当前功能切片。

## 结论

2026-10-16 用户审议通过 P0025 的候选实现及知识处置，并要求继续推进收尾；本决策转 accepted。

采用完整专家表的计算前校验与不可变快照、按编号有序的逐步 FP32 加法、合法非有限结果传播和嵌套既有阶段观测。保留 routed 部分和的精度与专家内部权重落点，不扩大既有组件职责。接口与数值正文唯一归 [MOE](../../docs/MOE.md)。

## 后果

- 快照成本与全部提供材料相关，不是生产加载或性能方案；旧路由与专家的数值和失败语义保持不变。
- 独立验证新增聚合舍入与排序，组合验证编号/权重接线；不重复证明上游全部算术。
- 后续生产聚合须对照本参照，完整 MoE 仍需共享专家与最终转换的独立验收；覆盖边界归 MODEL §4，操作归 BUILD §7。
