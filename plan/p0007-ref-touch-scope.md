## 意图

`tools/check_repo.py` 对任何触碰 `ref/` 的提交给出 W，首次建立 oracle 也会命中；`--audit` 扫描全部历史，P0006 一旦提交 oracle 代码，`--audit --strict` 将永久失败。禁区条文约束的是修改既有 oracle（不因引擎实现不便而修改；确认 oracle 自身有误时单独提交并写明依据）。本项把提醒收窄为第一父中已存在的 `ref/` 文件被修改、删除或改名，新建文件不再提醒，锚点与 W 级别不变。

## 验收

- [x] 新建 `ref/` 文件的普通提交与 `--no-ff` 合入，在 `--audit --strict` 下不产生 ref/ 提醒。
- [x] 修改、删除、改名既有 `ref/` 文件仍为 W；消息列出命中路径，不列同一提交新建的文件；合并提交按第一父判定。
- [x] 规则测试覆盖上述两侧，新建文件用例在修复前失败、修复后通过；全部规则测试、本仓库 `--audit --strict` 与 `git diff --check` 通过。
