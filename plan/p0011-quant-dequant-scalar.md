## 意图

在 [P0010](p0010-quant-scalar-baseline.md) 的生产 codec 与跨语言 parity 连接之上，交付 `ref/dequant.py` 对应的六类给定 scale 反量化生产入口，并逐位对照 `ref/`。成功标准是独立 C++ 消费者调用生产库，在声明的环境与输入契约下获得与 `ref/` 一致的 FP32 与 BF16 位模式。

本项是逐元素反量化与 dequant 类 kernel 的上一级参照，不是专家 FP4→FP8 GEMM、累加后乘 scale、提前 BF16 舍入或整数点积改写的参照；这些路径须另建参照另项验收。

## 验收

- [ ] **六类入口**：专家、普通 FP8 权重、Engram、SWA、主 KV、索引 K 六类反量化，各自支持 FP32 输出和 BF16 原始位模式输出。逐行分组、批维、二维块尾部与 scale shape 遵守 `docs/QUANT.md`，不广播、不转置、不推断 scale。BF16 输出只是独立的输出边界，不表示 GEMM 必须提前舍入。
- [ ] **输入与失败契约**：按 D0006 可判定地拒绝：rank、shape、数据长度、scale shape（含同元素数但 shape 错误）、输出容量、最后维不整除组大小、NaN 数据或 scale、非正或非有限 scale、索引与长度计算溢出、输入输出重叠。元数据校验在读取任何数据前完成，之后只读取已确认在界内的数据；内容校验在写入任何输出前完成；失败时输出不变；允许零元素张量。每类拒绝至少一个测试：元数据错误用短于声明的数据或 scale 缓冲区，在 `cpu-asan` 下证明拒绝前无越界读；内容错误把坏数据或坏 scale 放在最后一个元素，证明输出未被提前写入。
- [ ] **调用时数值环境**：按 D0006 在每次 bulk 调用前检查当前线程 MXCSR 的完整控制字段，不以 `fegetround()` 为依据。反例在同一进程内只经 `_mm_setcsr` 构造：舍入位分别设为向上、向下、向零，FTZ，DAZ，以及解除溢出掩码；另保留一个 `fesetround(FE_UPWARD)` 反例。每种环境下各入口均抛出约定的异常，不修改输出与浮点环境，进程不崩溃；恢复默认环境后结果正确。敏感性用例：MXCSR 仅设为向上舍入时，`-448 × 2^127`（E4M3FN 最大值乘 E8M0 `0xFE`）必须被拒绝，不能返回负的最大有限数。不以另一进程的 `bb.fp_env` 通过代替调用时证据。
- [ ] **乘 scale parity**：对照 `ref/`，覆盖既有数据编码与合法 scale 编码的全部有限组合、极端 scale、符号零、渐进下溢与上溢到 Inf，FP32 与 BF16 输出逐位比较；NaN 只比较分类。
- [ ] **布局边界**：每类入口覆盖多行、多组、批维、相邻不同 scale、行列不对称、二维块双尾块、组边界与零元素张量，确保 scale 错轴不能通过。随机用例只作可复现补充。
- [ ] **可复现、越界检查与测试敏感性**：`cpu-debug`、`cpu-release` 运行全部必选测试，`cpu-asan` 运行全部 quant 测试且无 sanitizer 报告；从源码目录外及干净检出验证。临时注入逐行 scale 索引、二维块尾部 scale 索引、批维步长、BF16 输出舍入四类错误，均被识别，恢复后全部通过。记录环境、命令与结果。
- [ ] **知识、治理与人工收尾**：经确认后，反量化入口契约、调用时环境要求与验证边界最小增补到 `docs/QUANT.md`，测试清单增补到 `docs/BUILD.md`。数值提交的 `Oracle:` 指向真实的 C++ parity 测试；仓库检查与合入前提交范围审计通过；用户评审后才结项。

## 记录

### 范围与依据

- 前置：P0010 completed，D0006 accepted。沿用 P0010 的模块、测试协议、执行器与 `cpu-asan` 配置，只扩展反量化操作。
- 范围外：有损编码与 scale 生成、动态激活/KV 量化、RoPE 与 cache 管理、点积 scale 折叠、整数点积、GEMM/GEMV、官方转换器的完整重分块、真实权重、CUDA 与 SIMD、性能论断。
- 数值依据：[QUANT §3～§5](../docs/QUANT.md#3-浮点运算与输出)、`ref/dequant.py`、[MODEL §2](../docs/MODEL.md#2-结构与格式)。

### 执行契约

- 乘 scale 用受 `df_strict_fp` 约束的宿主 binary32 乘法，以 `ref/` 的整数算术参照验证；不移植 Python 任意精度实现，不新增软件浮点库。解码沿用 P0010 的 codec，不能以解码 parity 代替乘法 parity。
- 环境检查只在本模块内实现，不提前建设 platform/core 模块。检查放在单独的非内联函数中，在首次读取输入数据前调用；GCC 不支持 `FENV_ACCESS`，不建模浮点环境，否则输入读取与乘法可能被提前到检查之前，解除掩码时在检查前就陷入 SIGFPE。

### 完成声明边界

- K-Q2 只覆盖给定 E8M0 的指数应用，不覆盖点积折叠；K-Q3 只覆盖给定 scale 的 KV/SWA 布局，不覆盖动态量化。不笼统勾选 K-Q1～K-Q3。
- 不新增性能论断或优化开关。

### 执行与知识处置

- 分支 `p0011-quant-dequant-scalar`；提交用 `P0011 quant:` 并带 `Oracle:`。顺序：先专家反量化打通，再补其余五类、失败契约、环境反例与敏感性注入。
- 知识预计为 updated；必要知识缺失阻塞结项。

### 设计记录

- 2026-10-11：P0010 评审后经用户同意，从 P0010 拆出本项，承接六类反量化、乘 scale parity、调用时环境检查与相应失败契约。仅登记 draft，未开始实现。
- 2026-10-11：用户评审指出 glibc 的 `fegetround()` 读取 x87 控制字，只改 MXCSR 的舍入不可见。本机探针确认，并发现解除溢出掩码会使上溢陷入 SIGFPE（见 D0006 实测前提）。经用户同意，环境检查改为以 MXCSR 完整控制字段为准，反例改为只经 `_mm_setcsr` 构造并加入上溢符号的敏感性用例。
