## 意图

先建立可独立验收、无需目标 GPU 或模型权重的数值参照，为后续量化格式与计算路径提供验证根。本项只交付 `ref/` 的第一块格式 oracle，不等同于完整 FP32 模型 oracle；不实现引擎或宣称与官方 GPU 执行逐位一致。

## 验收

- [ ] **覆盖格式与输出边界**：提供 E2M1 原始 nibble、E4M3FN 原始 byte、UE8M0/E8M0 原始 byte 到 FP32 的解码；明确具体格式变体，不以笼统的“FP8”代替。提供 BF16 位模式到 FP32，以及按有依据的舍入规则生成 BF16 位模式的转换。精确 FP32 解码、FP32 乘 scale、落到 BF16 的舍入分别验收，不抹掉官方路径中的 BF16 落点。
- [ ] **码点穷举与独立依据**：覆盖 E2M1 全部 16 个码点、E4M3FN 与 E8M0 各 256 个字节编码，以及 BF16 全部 65,536 个位模式的解码。正常值、次正规值、零及特殊编码按各格式实际语义判定；预期值来自可追溯的格式定义、独立位域/精确算术或官方常量，不调用被测函数生成，也不只复制被测 LUT。官方代码未充分定义的行为须补足权威依据，依据或关键语义未明确时不得验收。
- [ ] **E2M1 字节布局**：穷举 256 个 packed byte，验证低半字节在前及 `byte → nibble → byte` 逐位可逆；多行、不对称码点用例验证沿最后一维配对、不跨行打包。非法码点、奇数逻辑长度与不匹配的 shape 明确报错，不隐式截断或填充。不把 `byte → 数值 → byte` 当成全部编码可逆的验收条件。
- [ ] **E2M1 精确整数格**：全部码点的整数格结果与 FP32 解码值乘 2 精确相等，不使用近似误差。零码点与整数零之间的信息损失及零符号策略明确；若提供整数格反向接口，仅接受精确格点、拒绝非格点，并明确零的规范编码，不要求从整数格恢复全部原始位信息。
- [ ] **给定 scale 的反量化与布局**：覆盖专家 E2M1 + E8M0 沿 K 每 32 元素分组、普通 FP8 权重 E4M3 + E8M0 的二维 32×32 块、Engram/SWA 的 E4M3 + E8M0 沿最后一维每 32 元素分组、主 KV 的 E2M1 + E4M3 每 16 元素分组、索引 K 的 E2M1 + E8M0 每 32 元素分组。每类以多行、多组或多块、相邻不同 scale、行列不对称及组边界用例检查 scale 索引，避免错轴仍通过。二维块路径覆盖非整块尾部及向上取整的 scale shape；逐行分组路径要求最后一维整除组大小，错误 shape 明确拒绝。此处只覆盖已编码数据与给定 scale，不代表已实现 KV 动态量化、RoPE 或 cache 管理。
- [ ] **精度、特殊值与异常契约**：编码、打包字节及整数格精确比较；有限 FP32 解码与按 FP32 运算规则得到的反量化结果精确比较；BF16 输出比较位模式，编码方向覆盖舍入中点及其两侧、指数进位、正常/次正规边界、上溢/下溢和特殊输入。NaN 比较分类，除非有独立依据不承诺 payload 一致；零符号按声明策略检查。底层 codec 完整识别编码，模型反量化入口拒绝 NaN 和非正 scale；有效输入的 FP32 乘积上溢/下溢按明确浮点规则处理，不静默钳制。不以统一 `allclose` 掩盖格式错误，也不承诺任意 scale 乘积或 BF16 落点都能精确表示。
- [ ] **CPU 独立执行与证据**：`ref/` 代码与 `tests/quant/` 测试引用 P0006；一条明确的 CPU 命令可运行全部必选验收，不依赖 CUDA、TileLang 初始化、模型权重、目标机或官方 GPU dump，不导入官方 GPU kernel 生成预期结果。必选穷举和边界测试不得因某 dtype 的 CPU 支持缺失而跳过后宣称通过；随机测试仅作补充且可复现。记录解释器、依赖版本、CPU/平台、方法、命令及结果；CPU 库对照只有在确认所用操作受支持后才作为补充证据。
- [ ] **知识与验证边界处置**：格式依据、特殊值策略、FP32 运算及 BF16 舍入契约归档到 `docs/`，测试命令与环境、验收证据指针回填本项；不把长期规格重复留在计划正文。若落盘金标准字节到 `tests/data/`，按冻结区契约记录来源、生成方式并重算 manifest。结项时明确本项不证明动态量化、GPU cast、kernel parity 或端到端模型一致；完成 knowledge 处置并据实际情况回填真实接收项，不以本项完成替代 `src/quant` 或 K-Q1～K-Q3 的引擎实现验收。
