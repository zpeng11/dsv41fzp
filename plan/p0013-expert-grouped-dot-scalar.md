## 意图

接续 [P0012](p0012-expert-grouped-dot-oracle.md)，按 [COMPUTE](../docs/COMPUTE.md) 契约交付单输出专家分组点积的生产 C++ scalar 入口，并对照 `ref/compute.py` 逐阶段验证同一生产执行路径。成功标准：独立 C++ 消费者调用生产库，得到与 oracle 一致的 FP32 与 BF16 结果，有限值（含带符号零）及 Inf 按位一致，NaN 按分类一致；结果与调用线程的浮点环境无关。

本项是该契约 kernel 的上一级参照（[MODEL §4](../docs/MODEL.md#4-精确性链条)），数值路径、接口与观测方式的取舍见 [D0009](decisions/d0009-compute-scalar-integer-path.md)。不验收 SIMD/CUDA、K-E1/K-E2、官方 GPU 或端到端一致，不改变 W4A16 decode 默认规划。

## 验收

- [ ] **生产入口与失败契约**：`src/quant` 提供单输出入口，公共头 `include/df/quant/compute.h`；输入长度与分组按 COMPUTE §2，表示、输出重载与失败类按 D0009。K 为零或不整除 32、长度不匹配、输出容量不足、NaN 激活或 scale 编码、四份输入与实际输出前缀重叠，均抛 `std::invalid_argument`；每类按两种输出分别验证失败时整个输出缓冲区不变。坏内容置于输入末端，元数据错误配合短缓冲区，在 `cpu-asan` 下验证元数据校验先于内容读取、内容校验先于输出写入。Python 侧的类型、宽度与输出字符串拒绝仍由 oracle 验证；超宽 token 与未知输出模式由执行器按协议错误拒绝，不计为库拒绝。解码复用 P0010 codec，不扩展为矩阵算子。
- [ ] **整数构造数值路径**：逐条实现 COMPUTE §3，全部阶段按 D0009 以定宽整数构造，不执行浮点运算，不读写浮点环境。乘 scale 前先分流非有限操作数；合法计算产生的 Inf/NaN 照常传播，不是调用失败。舍入保持通用，不以"E4M3FN×E2M1 有限乘积恒精确"之类的输入性质作为正确性前提；不新增公共通用 IEEE 接口。
- [ ] **逐阶段计算 parity**：经 D0009 的私有观测连接对照 `ref/compute.py::trace_expert_grouped_dot`，比较每个元素乘积、每次块内累加、每块 `dot_bits` / `after_a_bits` / `block_bits`、每次 `acc_bits` 与最终 FP32/BF16；两种公开入口与对应观测结果一致。覆盖：全部有限 E4M3FN×E2M1 码点对（4,064 对）、双方 scale 编码边界、相邻不同 scale 多块、跨 128 元素边界的错组敏感布局、归约与 scale 次序敏感向量、RNE 中点及两侧、指数进位、正常/次正规边界、下溢到零、上溢到 Inf、零符号与 Inf/NaN 传播。定向证明：第二次 scale 乘法保留第一次产生的 Inf；块贡献 −0 在中间阶段检出；异号 Inf 产生的 NaN 在后续累加中传播。输入 NaN 只作库拒绝用例；随机用例仅作固定种子补充；不以最终输出、codec 或逐元素 dequant parity 代替。
- [ ] **定宽整数加法**：按 D0009 的表示实现，不允许移位越界、带符号整数溢出或丢弃影响舍入的低位。同一生产 helper 经私有连接对照 `ref/compute.py::_add_fp32`，覆盖大指数差、RNE 中点及两侧、sticky 敏感舍入、近相消、舍入与指数进位、正常/次正规边界、符号零与 Inf/NaN；公开 parity 另含 `0x7F000000 + 0x00000001`（`2^127 + 2^-149`）。全部专项在 `cpu-asan` 下无 UBSan 报告。
- [ ] **数值环境无关**：公开 parity 与加法专项在执行器既有的八种 MXCSR 设置下各运行一遍，结果与 `ref/` 一致，进程不陷入，每次调用前后（含拒绝路径）完整 MXCSR 不变。敏感用例含负次正规链、上溢带符号 Inf 与非默认舍入方向。
- [ ] **测试敏感性与失败传播**：在 scratch 独立副本中分别注入以下十类错误，每类由指定的定向用例产生数值比较失败：
  - scale 每四块共享；
  - 提前 BF16；
  - 跨块倒序；
  - 块贡献 −0 规范化：最终输出相同时由中间阶段检出；
  - 非有限中间值误送有限乘法；
  - 加法丢失 sticky：须命中指定舍入用例；
  - nibble 高低位颠倒：高低 nibble 不同且对应激活不对称，在乘积阶段检出；
  - 相邻配对平衡树归约：指定向量的最终结果须与顺序累加不同；
  - 两份 scale 交换；
  - 两份 scale 折叠。

  scale 交换与折叠的锚点为 dot=2、scale_a=`0xFE`、scale_b=`0x00`：规定次序得 Inf，交换或折叠得 2。恢复后全部测试通过，交付源字节不变。harness 沿用 P0010/P0011 协议，覆盖崩溃、非零退出、乱码、少响应与坏请求；trace 响应须检查阶段数量与位宽。错误结果或异常必须导致非零退出，但不以任意非零退出代替数值敏感性。
- [ ] **构建、治理与复现**：三个 CPU preset 构建并通过既有与新增测试；新增测试接入 `tests/quant` 的 quant CTest 序列，compute 进入 `cpu-asan` 所构建的 quant 生产库，不新增 preset。数值提交带 `Oracle:`；`python3 tools/check_repo.py --strict` 与提交范围审计 E=0 W=0 I=0；从源码目录外及干净检出复现，既有 oracle 测试回归通过。
- [ ] **知识与人工收尾**：经用户确认后，生产入口与失败契约、特殊值分流、验证边界与环境要求最小增补到 COMPUTE（与 Python 拒绝类分开），测试入口增补到 BUILD，必要时更新 MODEL §4 与 STATUS。用户评审后才结项。

- 前置：P0012 completed；P0010/P0011 的生产 codec、有限乘法、BF16 舍入、跨语言 parity 协议与 MXCSR 环境矩阵可复用。逐元素反量化的有限输入前提不能外推到计算中间值，Python 拒绝类也不能直接转为 C++ 失败类。
