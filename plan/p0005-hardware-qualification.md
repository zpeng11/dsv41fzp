## 意图

承接 P0004 支持矩阵修订后的执行义务，按 docs/HARDWARE.md 实现硬件资质检查并接入 deploy 启动前预检。首台 RTX PRO 6000 Blackwell 目标机须以真实拓扑、驱动与逐对数据正确性证明 PCIe P2P 可用，不以卡名、接口代际或 topo 输出替代测试。

本项尚未启动；需要可访问的目标机与可执行 CUDA 探针的构建环境。具体工具实现及实验方案在开工时细化并评审，不由本草案推定未知的驱动最低版本或性能阈值。

## 验收

- [ ] 实现型号、同型号多卡、运行环境、NUMA 与链路配置检查，以及逐对双向 P2P 能力和启用验证；无 NVLink 本身不拒绝 PRO 6000，无 GPU P2P 则拒启。
- [ ] 真实 GPU 间读写与拷贝校验覆盖所有有向卡对；不可达、数据不一致与测试超时均拒启，不将 host staging 冒充 P2P 通过。
- [ ] deploy 使用资格检查结果决定是否启动；保存可审计的环境、拓扑、检查项与失败原因，适配既有 NVLink 机型。
- [ ] 增加正反例自动化测试，并在目标机上归档正确性、带宽、延迟、并发竞争及 GPU 到 pinned 池 DMA 的实测证据；bench 记录带环境、方法、version、git_sha 与 dirty。
- [ ] 实测后评审驱动/CUDA 配置与性能资格阈值，更新 HARDWARE；用户验收前不宣称已获整机部署资质。
